## 1.1 ความเป็นมาและความสำคัญของโครงงาน

ในปัจจุบัน องค์กรขนาดใหญ่ เช่น โรงพยาบาล สถานศึกษา และหน่วยงานราชการ นิยมใช้จอแสดงผลเพื่อประชาสัมพันธ์ข้อมูลข่าวสารแก่ผู้มาใช้บริการตามจุดต่าง ๆ ภายในอาคาร ระบบลักษณะนี้เรียกว่า "ระบบป้ายประชาสัมพันธ์ดิจิทัล" (Digital Signage) ซึ่งช่วยให้การสื่อสารข้อมูลทำได้รวดเร็วและปรับเปลี่ยนได้ตลอดเวลา อย่างไรก็ตาม เมื่อจำนวนจอเพิ่มมากขึ้นและกระจายอยู่หลายจุด การบริหารจัดการเนื้อหาและการควบคุมจอแต่ละเครื่องด้วยวิธีเดิม เช่น การนำไฟล์ใส่อุปกรณ์ USB ไปเสียบที่จอทีละเครื่อง หรือการเดินไปเปิด-ปิดจอด้วยมือ ก่อให้เกิดปัญหาหลายประการ ได้แก่ ความล่าช้าในการอัปเดตเนื้อหา ความไม่สอดคล้องของข้อมูลระหว่างจอ ความยากในการกำหนดตารางการแสดงผล และการขาดช่องทางในการประกาศข้อมูลเร่งด่วนหรือเหตุฉุกเฉินได้ทันท่วงที

จากปัญหาดังกล่าว ผู้จัดทำจึงได้พัฒนา "ระบบจัดการจอประชาสัมพันธ์ดิจิทัล (Digital Signage Management System)" ขึ้น เพื่อรวมการจัดการเนื้อหา การจัดผังการแสดงผล (layout) การกำหนดตารางเวลาออกอากาศ (schedule) การควบคุมจอโทรทัศน์ระยะไกล ตลอดจนการประกาศเหตุฉุกเฉิน ไว้ในระบบกลางเพียงระบบเดียว ผู้ดูแลสามารถสั่งงานผ่านเว็บแอปพลิเคชันจากศูนย์กลางได้ โดยไม่ต้องเดินไปจัดการที่หน้าจอแต่ละเครื่อง ช่วยลดทั้งเวลาและความผิดพลาดในการดำเนินงาน

ระบบออกแบบให้ทำงานภายในเครือข่ายภายในองค์กร (LAN) รองรับการเล่นเนื้อหาแบบ offline-friendly ผ่านไฟล์ manifest เพื่อให้จอยังแสดงผลต่อได้แม้เครือข่ายขัดข้องชั่วคราว มีระบบสิทธิ์ผู้ใช้ (RBAC) และกระบวนการอนุมัติเนื้อหาเพื่อความปลอดภัยและความถูกต้องของข้อมูล รวมถึงการบันทึกประวัติการใช้งาน (audit log) และการเฝ้าระวังสถานะอุปกรณ์ นอกจากนี้ยังพัฒนาด้วยเทคโนโลยี Open Source ทั้งหมด และติดตั้งด้วย Docker เพื่อให้ปรับใช้และดูแลรักษาได้ง่าย ลดต้นทุนค่าลิขสิทธิ์ซอฟต์แวร์

## 1.2 วัตถุประสงค์ของโครงงาน

1. เพื่อพัฒนาระบบจัดการเนื้อหาและตารางการแสดงผลของจอประชาสัมพันธ์จากศูนย์กลาง
2. เพื่อรองรับการควบคุมจอโทรทัศน์ระยะไกล (เปิด/ปิด/เปลี่ยนช่องสัญญาณเข้า) ผ่านโปรโตคอล HDMI-CEC และ RS-232 ได้หลายยี่ห้อ
3. เพื่อจัดให้มีระบบสิทธิ์ผู้ใช้ (RBAC) และกระบวนการอนุมัติเนื้อหาและตารางก่อนเผยแพร่
4. เพื่อรองรับการประกาศเหตุฉุกเฉินที่สามารถแทรก (override) ตารางการแสดงผลปกติได้ทันที
5. เพื่อเฝ้าระวังสถานะของอุปกรณ์และบันทึกประวัติการกระทำ (audit log) ทุกรายการ
6. เพื่อพัฒนาระบบด้วยเทคโนโลยี Open Source และสามารถติดตั้งใช้งานด้วย Docker ได้

## 1.3 ขอบเขตของโครงงาน

### 1.3.1 ขอบเขตด้านปริมาณการใช้งาน
รองรับการบริหารจัดการจอประชาสัมพันธ์ระดับ 10–20 จุด (ขนาด Proof of Concept) และสามารถขยายจำนวนได้ผ่านการจัดกลุ่มจอ (player group)

### 1.3.2 แพลตฟอร์มของจอแสดงผลที่รองรับ
รองรับ Android TV, แท็บเล็ต Android, Raspberry Pi (โหมด kiosk), เครื่องคอมพิวเตอร์ Windows และเว็บเบราว์เซอร์ (PWA)

### 1.3.3 การควบคุมจอโทรทัศน์และอุปกรณ์แสดงผล
รองรับการสั่งงานทีวีผ่าน HDMI-CEC และ RS-232 ได้หลายยี่ห้อ (เช่น Samsung MDC, LG, Sony) รวมถึงการควบคุมจอ LED ผ่านโมดูลควบคุม LED

### 1.3.4 ชนิดของเนื้อหาที่รองรับ
รองรับเนื้อหาประเภทรูปภาพ (image) วิดีโอ (video) หน้าเว็บ (web) สตรีม (stream) และข้อความ (text)

### 1.3.5 การติดตั้งและการนำไปใช้งาน
ออกแบบให้ติดตั้งแบบ on-premise บนระบบปฏิบัติการ Linux (Ubuntu 22.04) ด้วย Docker Compose

### 1.3.6 ข้อจำกัดของโครงงาน
เป็นการพัฒนาระบบใหม่ (greenfield) จึงไม่รวมการย้ายข้อมูลจากระบบเดิม (data migration)

## 1.4 ประโยชน์ที่คาดว่าจะได้รับ

1. ลดเวลาและข้อผิดพลาดในการอัปเดตเนื้อหา เนื่องจากบริหารจัดการได้จากศูนย์กลาง
2. ลดภาระการเดินไปควบคุมจอแต่ละเครื่อง ด้วยการสั่งเปิด/ปิด/เปลี่ยนสัญญาณจากระยะไกล
3. เพิ่มความปลอดภัยและความถูกต้องของข้อมูล ด้วยระบบสิทธิ์ผู้ใช้และกระบวนการอนุมัติ
4. สามารถสื่อสารข้อมูลเร่งด่วนหรือเหตุฉุกเฉินไปยังทุกจอได้ทันที
5. ลดต้นทุนค่าลิขสิทธิ์ซอฟต์แวร์ ด้วยการใช้เทคโนโลยี Open Source
6. ได้ระบบต้นแบบที่สามารถนำไปขยายผลและต่อยอดในองค์กรจริงได้

## 1.5 หน้าที่ความรับผิดชอบของผู้จัดทำ
