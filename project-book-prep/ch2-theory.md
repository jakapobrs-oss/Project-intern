# บทที่ 2
# ทฤษฎีและเทคโนโลยีที่เกี่ยวข้อง

> ร่างเนื้อหาภาษาไทย — แต่ละหัวข้อมีรูปประกอบ (โลโก้/ไดอะแกรม) ตาม format เดชธนา

ในบทนี้กล่าวถึงทฤษฎีและเทคโนโลยีที่นำมาใช้ในการพัฒนาระบบจัดการจอประชาสัมพันธ์ดิจิทัล เพื่อให้เข้าใจหลักการทำงานของเครื่องมือแต่ละส่วนก่อนนำไปสู่การออกแบบและพัฒนาในบทต่อไป

## 2.1 ระบบป้ายประชาสัมพันธ์ดิจิทัล (Digital Signage)

ระบบป้ายประชาสัมพันธ์ดิจิทัล คือระบบที่ใช้จอแสดงผลอิเล็กทรอนิกส์ในการนำเสนอเนื้อหาดิจิทัล เช่น รูปภาพ วิดีโอ และข้อความ โดยสามารถควบคุมและปรับเปลี่ยนเนื้อหาจากศูนย์กลางผ่านเครือข่าย องค์ประกอบหลักประกอบด้วยส่วนจัดการเนื้อหา (Content Management) ส่วนแสดงผลที่ติดตั้งกับจอ (Player) และช่องทางสื่อสารระหว่างสองส่วนนี้ ทำให้องค์กรสามารถอัปเดตเนื้อหาและกำหนดตารางการแสดงผลล่วงหน้าได้อย่างมีประสิทธิภาพ

[[FIG|2.1|file:assets/fig-signage-overview.svg|องค์ประกอบของระบบป้ายประชาสัมพันธ์ดิจิทัล|mid]]

## 2.2 FastAPI และภาษา Python

FastAPI เป็นเว็บเฟรมเวิร์กภาษา Python สำหรับสร้าง REST API ที่ทำงานแบบ asynchronous มีจุดเด่นด้านประสิทธิภาพสูง การตรวจสอบชนิดข้อมูลด้วย type hints และการสร้างเอกสาร API อัตโนมัติในรูปแบบ OpenAPI (Swagger) ในระบบนี้ใช้ FastAPI 0.115 ร่วมกับ Python 3.12 เป็นแกนหลักของฝั่ง backend สำหรับจัดการตรรกะทางธุรกิจและให้บริการ API แก่ส่วนอื่น ๆ

[[FIG|2.2|fastapi|FastAPI]]

## 2.3 PostgreSQL, SQLAlchemy และ Alembic

PostgreSQL เป็นระบบจัดการฐานข้อมูลเชิงสัมพันธ์ (RDBMS) แบบ open source ที่มีความเสถียรและรองรับข้อมูลปริมาณมาก ระบบนี้ใช้ PostgreSQL 16 เป็นฐานข้อมูลหลัก โดยเข้าถึงผ่าน SQLAlchemy 2.x ซึ่งเป็น Object-Relational Mapping (ORM) แบบ async และใช้ Alembic ในการจัดการการเปลี่ยนแปลงโครงสร้างฐานข้อมูล (migration) อย่างเป็นระบบ

[[FIG|2.3|postgresql|PostgreSQL]]

## 2.4 Next.js, TypeScript และ Tailwind CSS

Next.js เป็นเฟรมเวิร์กที่พัฒนาต่อยอดจาก React สำหรับสร้างเว็บแอปพลิเคชันที่รองรับทั้ง server-side rendering และ static generation ใช้ร่วมกับ TypeScript เพื่อเพิ่มความปลอดภัยด้านชนิดข้อมูล และ Tailwind CSS ซึ่งเป็น Utility-first CSS Framework สำหรับออกแบบหน้าตาให้ทันสมัยและรองรับการแสดงผลหลายขนาดหน้าจอ (responsive) ในระบบนี้ใช้สร้างหน้าจอส่วนจัดการสำหรับผู้ดูแล (Admin UI)

[[FIG|2.4|nextdotjs|Next.js]]

## 2.5 Redis และ Arq

Redis เป็นฐานข้อมูลแบบ in-memory ที่ทำงานได้รวดเร็ว ใช้สำหรับเก็บข้อมูลชั่วคราว (cache) และทำหน้าที่เป็นตัวกลางรับส่งข้อความ (message broker) ส่วน Arq เป็นตัวจัดคิวงาน (task queue) แบบ async ที่ทำงานร่วมกับ Redis ใช้รันงานเบื้องหลัง เช่น การหมดอายุของประกาศฉุกเฉินอัตโนมัติ การประมวลผลไฟล์สื่อ และคิวคำสั่งควบคุมทีวี

[[FIG|2.5|redis|Redis]]

## 2.6 MinIO

MinIO เป็นระบบจัดเก็บไฟล์แบบ object storage ที่เข้ากันได้กับ Amazon S3 API สามารถติดตั้งใช้งานภายในองค์กรเองได้ ในระบบนี้ใช้ MinIO สำหรับจัดเก็บไฟล์สื่อ เช่น รูปภาพและวิดีโอ ที่ผู้ใช้อัปโหลดเข้ามา

[[FIG|2.6|minio|MinIO]]

## 2.7 Docker และการทำคอนเทนเนอร์ (Containerization)

Docker เป็นเทคโนโลยีที่ช่วยบรรจุแอปพลิเคชันพร้อมสภาพแวดล้อมการทำงานไว้ในคอนเทนเนอร์ ทำให้ติดตั้งและทำงานได้เหมือนกันในทุกเครื่อง ระบบนี้ใช้ Docker Compose ในการจัดการบริการทั้งหมด (backend, worker, ฐานข้อมูล, Redis, MinIO, Admin UI) ให้ทำงานร่วมกัน ทำให้ติดตั้งระบบทั้งหมดได้ด้วยคำสั่งเดียว

[[FIG|2.7|docker|Docker]]

## 2.8 HDMI-CEC และ RS-232

HDMI-CEC (Consumer Electronics Control) เป็นโปรโตคอลที่ส่งคำสั่งควบคุมอุปกรณ์ผ่านสาย HDMI เช่น การสั่งเปิด-ปิดทีวี ส่วน RS-232 เป็นมาตรฐานการสื่อสารแบบ serial ที่ทีวีระดับองค์กรหลายยี่ห้อรองรับสำหรับการควบคุมจากระยะไกล ระบบนี้ใช้ทั้งสองโปรโตคอลในการสั่งเปิด/ปิด/เปลี่ยนช่องสัญญาณเข้าของทีวีหลายยี่ห้อ (เช่น Samsung MDC, LG, Sony)

[[FIG|2.8|file:assets/fig-cec-rs232.svg|การควบคุมจอโทรทัศน์ผ่าน HDMI-CEC และ RS-232|mid]]

## 2.9 ความปลอดภัยของระบบ (Security)

ระบบให้ความสำคัญกับความปลอดภัยหลายระดับ ได้แก่ การยืนยันตัวตนด้วย JWT (JSON Web Token) ร่วมกับระบบสิทธิ์ตามบทบาท (Role-Based Access Control: RBAC), การสแกนไวรัสไฟล์ที่อัปโหลดด้วย ClamAV, และการป้องกันการโจมตีแบบ SSRF (Server-Side Request Forgery) ด้วยการตรวจสอบ URL ที่ผู้ใช้ส่งเข้ามาไม่ให้ชี้เข้าสู่เครือข่ายภายใน

[[FIG|2.9|file:assets/fig-security-layers.svg|มาตรการความปลอดภัยของระบบ|mid]]
