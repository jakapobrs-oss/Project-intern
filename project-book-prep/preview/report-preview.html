บทคัดย่อ mkr1mkr

ระบบจัดการจอประชาสัมพันธ์ดิจิทัล (Digital Signage Management System) พัฒนาขึ้นเพื่อแก้ปัญหาการบริหารจัดการจอประชาสัมพันธ์หลายจุดในองค์กรที่เดิมต้องอัปเดตเนื้อหาและควบคุมจอด้วยมือทีละเครื่อง โดยรวมการจัดการเนื้อหา การจัดผังการแสดงผล การกำหนดตารางเวลาออกอากาศ การควบคุมจอโทรทัศน์และจอ LED ระยะไกลผ่านโปรโตคอล HDMI-CEC และ RS-232 ตลอดจนการประกาศเหตุฉุกเฉิน ไว้ในระบบกลางเพียงระบบเดียว

ระบบพัฒนาด้วยสถาปัตยกรรมแบบบริการหลายส่วน (FastAPI, PostgreSQL, Redis, MinIO และ Next.js) ทำงานในรูปแบบคอนเทนเนอร์ด้วย Docker มีระบบสิทธิ์ผู้ใช้แบบ RBAC กระบวนการอนุมัติเนื้อหา การบันทึกประวัติการใช้งาน และการเฝ้าระวังสถานะอุปกรณ์ ส่วนแสดงผลรองรับการทำงานแบบ offline-friendly ผ่านไฟล์ manifest ผลการพัฒนาได้ระบบที่ใช้งานได้ครบวงจรพร้อมการทดสอบอัตโนมัติประมาณ 133 กรณี

คำสำคัญ: ป้ายประชาสัมพันธ์ดิจิทัล, การจัดการเนื้อหา, การควบคุมทีวีระยะไกล, HDMI-CEC, RS-232, FastAPI

ABSTRACT mkr2mkr

The Digital Signage Management System was developed to address the challenge of managing multiple public-display screens within an organization, which previously required manual content updates and per-device screen control. The system consolidates content management, layout composition, broadcast scheduling, remote control of televisions and LED displays via HDMI-CEC and RS-232, and emergency announcements into a single centralized platform.

Built on a multi-service architecture (FastAPI, PostgreSQL, Redis, MinIO, and Next.js) running in Docker containers, the system provides role-based access control (RBAC), a content approval workflow, audit logging, and device monitoring. The player supports offline-friendly operation through manifest files. The result is a fully functional system accompanied by approximately 133 automated test cases.

Keywords: Digital Signage, Content Management, Remote TV Control, HDMI-CEC, RS-232, FastAPI

1.1 ความเป็นมาและความสำคัญของโครงงาน mkr5mkr

ในปัจจุบัน องค์กรขนาดใหญ่ เช่น โรงพยาบาล สถานศึกษา และหน่วยงานราชการ นิยมใช้จอแสดงผลเพื่อประชาสัมพันธ์ข้อมูลข่าวสารแก่ผู้มาใช้บริการตามจุดต่าง ๆ ภายในอาคาร ระบบลักษณะนี้เรียกว่า "ระบบป้ายประชาสัมพันธ์ดิจิทัล" (Digital Signage) ซึ่งช่วยให้การสื่อสารข้อมูลทำได้รวดเร็วและปรับเปลี่ยนได้ตลอดเวลา อย่างไรก็ตาม เมื่อจำนวนจอเพิ่มมากขึ้นและกระจายอยู่หลายจุด การบริหารจัดการเนื้อหาและการควบคุมจอแต่ละเครื่องด้วยวิธีเดิม เช่น การนำไฟล์ใส่อุปกรณ์ USB ไปเสียบที่จอทีละเครื่อง หรือการเดินไปเปิด-ปิดจอด้วยมือ ก่อให้เกิดปัญหาหลายประการ ได้แก่ ความล่าช้าในการอัปเดตเนื้อหา ความไม่สอดคล้องของข้อมูลระหว่างจอ ความยากในการกำหนดตารางการแสดงผล และการขาดช่องทางในการประกาศข้อมูลเร่งด่วนหรือเหตุฉุกเฉินได้ทันท่วงที

จากปัญหาดังกล่าว ผู้จัดทำจึงได้พัฒนา "ระบบจัดการจอประชาสัมพันธ์ดิจิทัล (Digital Signage Management System)" ขึ้น เพื่อรวมการจัดการเนื้อหา การจัดผังการแสดงผล (layout) การกำหนดตารางเวลาออกอากาศ (schedule) การควบคุมจอโทรทัศน์ระยะไกล ตลอดจนการประกาศเหตุฉุกเฉิน ไว้ในระบบกลางเพียงระบบเดียว ผู้ดูแลสามารถสั่งงานผ่านเว็บแอปพลิเคชันจากศูนย์กลางได้ โดยไม่ต้องเดินไปจัดการที่หน้าจอแต่ละเครื่อง ช่วยลดทั้งเวลาและความผิดพลาดในการดำเนินงาน

ระบบออกแบบให้ทำงานภายในเครือข่ายภายในองค์กร (LAN) รองรับการเล่นเนื้อหาแบบ offline-friendly ผ่านไฟล์ manifest เพื่อให้จอยังแสดงผลต่อได้แม้เครือข่ายขัดข้องชั่วคราว มีระบบสิทธิ์ผู้ใช้ (RBAC) และกระบวนการอนุมัติเนื้อหาเพื่อความปลอดภัยและความถูกต้องของข้อมูล รวมถึงการบันทึกประวัติการใช้งาน (audit log) และการเฝ้าระวังสถานะอุปกรณ์ นอกจากนี้ยังพัฒนาด้วยเทคโนโลยี Open Source ทั้งหมด และติดตั้งด้วย Docker เพื่อให้ปรับใช้และดูแลรักษาได้ง่าย ลดต้นทุนค่าลิขสิทธิ์ซอฟต์แวร์

FastAPI เป็นเว็บเฟรมเวิร์กภาษา Python สำหรับสร้าง REST API ที่ทำงานแบบ asynchronous มีจุดเด่นด้านประสิทธิภาพสูง การตรวจสอบชนิดข้อมูลด้วย type hints และการสร้างเอกสาร API อัตโนมัติในรูปแบบ OpenAPI (Swagger) ในระบบนี้ใช้ FastAPI 0.115 ร่วมกับ Python 3.12 เป็นแกนหลักของฝั่ง backend สำหรับจัดการตรรกะทางธุรกิจและให้บริการ API แก่ส่วนอื่น ๆ

2.3 PostgreSQL, SQLAlchemy และ Alembic mkr18mkr

PostgreSQL เป็นระบบจัดการฐานข้อมูลเชิงสัมพันธ์ (RDBMS) แบบ open source ที่มีความเสถียรและรองรับข้อมูลปริมาณมาก ระบบนี้ใช้ PostgreSQL 16 เป็นฐานข้อมูลหลัก โดยเข้าถึงผ่าน SQLAlchemy 2.x ซึ่งเป็น Object-Relational Mapping (ORM) แบบ async และใช้ Alembic ในการจัดการการเปลี่ยนแปลงโครงสร้างฐานข้อมูล (migration) อย่างเป็นระบบ

2.4 Next.js, TypeScript และ Tailwind CSS mkr19mkr

Next.js เป็นเฟรมเวิร์กที่พัฒนาต่อยอดจาก React สำหรับสร้างเว็บแอปพลิเคชันที่รองรับทั้ง server-side rendering และ static generation ใช้ร่วมกับ TypeScript เพื่อเพิ่มความปลอดภัยด้านชนิดข้อมูล และ Tailwind CSS ซึ่งเป็น Utility-first CSS Framework สำหรับออกแบบหน้าตาให้ทันสมัยและรองรับการแสดงผลหลายขนาดหน้าจอ (responsive) ในระบบนี้ใช้สร้างหน้าจอส่วนจัดการสำหรับผู้ดูแล (Admin UI)

2.5 Redis และ Arq mkr20mkr

Redis เป็นฐานข้อมูลแบบ in-memory ที่ทำงานได้รวดเร็ว ใช้สำหรับเก็บข้อมูลชั่วคราว (cache) และทำหน้าที่เป็นตัวกลางรับส่งข้อความ (message broker) ส่วน Arq เป็นตัวจัดคิวงาน (task queue) แบบ async ที่ทำงานร่วมกับ Redis ใช้รันงานเบื้องหลัง เช่น การหมดอายุของประกาศฉุกเฉินอัตโนมัติ การประมวลผลไฟล์สื่อ และคิวคำสั่งควบคุมทีวี

2.6 MinIO mkr21mkr

MinIO เป็นระบบจัดเก็บไฟล์แบบ object storage ที่เข้ากันได้กับ Amazon S3 API สามารถติดตั้งใช้งานภายในองค์กรเองได้ ในระบบนี้ใช้ MinIO สำหรับจัดเก็บไฟล์สื่อ เช่น รูปภาพและวิดีโอ ที่ผู้ใช้อัปโหลดเข้ามา

2.7 Docker และการทำคอนเทนเนอร์ (Containerization) mkr22mkr

Docker เป็นเทคโนโลยีที่ช่วยบรรจุแอปพลิเคชันพร้อมสภาพแวดล้อมการทำงานไว้ในคอนเทนเนอร์ ทำให้ติดตั้งและทำงานได้เหมือนกันในทุกเครื่อง ระบบนี้ใช้ Docker Compose ในการจัดการบริการทั้งหมด (backend, worker, ฐานข้อมูล, Redis, MinIO, Admin UI) ให้ทำงานร่วมกัน ทำให้ติดตั้งระบบทั้งหมดได้ด้วยคำสั่งเดียว

2.8 HDMI-CEC และ RS-232 mkr23mkr

HDMI-CEC (Consumer Electronics Control) เป็นโปรโตคอลที่ส่งคำสั่งควบคุมอุปกรณ์ผ่านสาย HDMI เช่น การสั่งเปิด-ปิดทีวี ส่วน RS-232 เป็นมาตรฐานการสื่อสารแบบ serial ที่ทีวีระดับองค์กรหลายยี่ห้อรองรับสำหรับการควบคุมจากระยะไกล ระบบนี้ใช้ทั้งสองโปรโตคอลในการสั่งเปิด/ปิด/เปลี่ยนช่องสัญญาณเข้าของทีวีหลายยี่ห้อ (เช่น Samsung MDC, LG, Sony)

2.9 ความปลอดภัยของระบบ (Security) mkr24mkr

ระบบให้ความสำคัญกับความปลอดภัยหลายระดับ ได้แก่ การยืนยันตัวตนด้วย JWT (JSON Web Token) ร่วมกับระบบสิทธิ์ตามบทบาท (Role-Based Access Control: RBAC), การสแกนไวรัสไฟล์ที่อัปโหลดด้วย ClamAV, และการป้องกันการโจมตีแบบ SSRF (Server-Side Request Forgery) ด้วยการตรวจสอบ URL ที่ผู้ใช้ส่งเข้ามาไม่ให้ชี้เข้าสู่เครือข่ายภายใน

3.1 การวิเคราะห์ความต้องการของระบบ mkr26mkr

3.3.1 สถาปัตยกรรมระบบ (System Architecture) mkr31mkr

โครงงานนี้ได้พัฒนาระบบจัดการจอประชาสัมพันธ์ดิจิทัล (Digital Signage Management System) จนสามารถใช้งานได้ครบวงจร ตั้งแต่การจัดการเนื้อหา การจัดผังการแสดงผล การกำหนดตารางเวลา การควบคุมจอโทรทัศน์และจอ LED ระยะไกล ไปจนถึงการประกาศเหตุฉุกเฉินและการเฝ้าระวังสถานะอุปกรณ์ ระบบทำงานบนสถาปัตยกรรม 6 ส่วนในรูปแบบคอนเทนเนอร์ มีส่วนจัดการสำหรับผู้ดูแล (Admin UI) และส่วนแสดงผล (Player) ทั้งบนเว็บและ Android ที่พร้อมใช้งานจริง โดยบรรลุวัตถุประสงค์ทั้งหมดที่ตั้งไว้ในบทที่ 1

ในด้านคุณภาพ ระบบมีกรณีทดสอบอัตโนมัติประมาณ 133 กรณี ครอบคลุมส่วนสำคัญของระบบ และมีระบบ CI ตรวจสอบความถูกต้องและความปลอดภัยทุกครั้งที่แก้ไขโค้ด

5.2 ปัญหาที่พบและแนวทางแก้ไข mkr44mkr

ปัญหาที่พบแนวทางแก้ไข
เครือข่ายภายในอาจขัดข้องชั่วคราว ทำให้จอหยุดแสดงผลออกแบบให้ player ดึง manifest แล้ว cache เนื้อหาไว้ เล่นต่อได้แบบ offline-friendly
ทีวีมีหลายยี่ห้อ คำสั่งควบคุมต่างกันออกแบบชั้นควบคุมแบบ enum protocol รองรับหลายยี่ห้อผ่าน HDMI-CEC และ RS-232
ความเสี่ยงด้านความปลอดภัยจากไฟล์อัปโหลดและ URL ภายนอกเพิ่มการสแกนไวรัสด้วย ClamAV และการป้องกัน SSRF ในการตรวจสอบ URL
ต้องควบคุมสิทธิ์การเข้าถึงและตรวจสอบย้อนหลังได้ใช้ระบบ RBAC 7 บทบาท ร่วมกับกระบวนการอนุมัติและการบันทึก audit log

5.3 ข้อเสนอแนะและการพัฒนาต่อยอด mkr45mkr

แนวทางการพัฒนาต่อยอดในอนาคต (Phase 7) ได้แก่

  1. รองรับ HDMI-CEC แบบ native บนอุปกรณ์แสดงผลให้สมบูรณ์ยิ่งขึ้น
  2. เสริมความปลอดภัยของการยืนยันตัวตนด้วย httpOnly cookie
  3. รองรับหลายภาษา (i18n) ในส่วนจัดการ
  4. ขยายระบบ CI/CD ให้ครอบคลุมการ deploy อัตโนมัติ
  5. เพิ่มตารางข้อมูลแบบ time-series สำหรับ telemetry เพื่อวิเคราะห์แนวโน้มของอุปกรณ์
