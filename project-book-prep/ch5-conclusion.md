# บทที่ 5
# สรุปผลและข้อเสนอแนะ

> ร่างเนื้อหาภาษาไทย · ฐาน: `internship-book-materials.md` §12

## 5.1 สรุปผลการดำเนินงาน

โครงงานนี้ได้พัฒนาระบบจัดการจอประชาสัมพันธ์ดิจิทัล (Digital Signage Management System) จนสามารถใช้งานได้ครบวงจร ตั้งแต่การจัดการเนื้อหา การจัดผังการแสดงผล การกำหนดตารางเวลา การควบคุมจอโทรทัศน์และจอ LED ระยะไกล ไปจนถึงการประกาศเหตุฉุกเฉินและการเฝ้าระวังสถานะอุปกรณ์ ระบบทำงานบนสถาปัตยกรรม 6 ส่วนในรูปแบบคอนเทนเนอร์ มีส่วนจัดการสำหรับผู้ดูแล (Admin UI) และส่วนแสดงผล (Player) ทั้งบนเว็บและ Android โดยส่วนแสดงผลบนเว็บได้รับการทดสอบการใช้งานจริงตั้งแต่การจับคู่อุปกรณ์จนถึงการแสดงเนื้อหาและประกาศฉุกเฉินเต็มจอแล้ว ซึ่งบรรลุวัตถุประสงค์ทั้งหมดที่ตั้งไว้ในบทที่ 1

ในด้านคุณภาพ ระบบผ่านการทดสอบอัตโนมัติครบทั้ง 142 กรณี ครอบคลุมส่วนสำคัญของระบบ ผ่านการทดสอบแบบ End-to-End ครบทั้ง 10 ขั้นตอนบนฐานข้อมูลจริง และผ่านการทดสอบการเข้ารหัสคำสั่งควบคุมจอโทรทัศน์ครบทั้ง 47 รูปแบบด้วยตัวจำลอง อีกทั้งมีระบบ CI ตรวจสอบความถูกต้องและความปลอดภัยทุกครั้งที่แก้ไขโค้ด

## 5.2 ปัญหาที่พบและแนวทางแก้ไข

ระหว่างการพัฒนาพบปัญหาสำคัญและได้ดำเนินการแก้ไข สรุปได้ดังตารางที่ 5.1

[[TBL|5.1|ปัญหาที่พบและแนวทางแก้ไข]]

| ปัญหาที่พบ | แนวทางแก้ไข |
|---|---|
| เครือข่ายภายในอาจขัดข้องชั่วคราว ทำให้จอหยุดแสดงผล | ออกแบบให้ player ดึง manifest แล้ว cache เนื้อหาไว้ เล่นต่อได้แบบ offline-friendly |
| ทีวีมีหลายยี่ห้อ คำสั่งควบคุมต่างกัน | ออกแบบชั้นควบคุมแบบ enum protocol รองรับหลายยี่ห้อผ่าน HDMI-CEC และ RS-232 |
| ความเสี่ยงด้านความปลอดภัยจากไฟล์อัปโหลดและ URL ภายนอก | เพิ่มการสแกนไวรัสด้วย ClamAV และการป้องกัน SSRF ในการตรวจสอบ URL |
| ต้องควบคุมสิทธิ์การเข้าถึงและตรวจสอบย้อนหลังได้ | ใช้ระบบ RBAC 7 บทบาท ร่วมกับกระบวนการอนุมัติและการบันทึก audit log |

## 5.3 ข้อเสนอแนะและการพัฒนาต่อยอด

แนวทางการพัฒนาต่อยอดในอนาคต (Phase 7) ได้แก่
1. ทดสอบการควบคุมกับจอโทรทัศน์และจอ LED จริงหลายยี่ห้อ เพื่อยืนยันผลที่ได้จากตัวจำลองในหัวข้อ 3.5.3 รวมถึงติดตั้งส่วนแสดงผลบน Android TV และ Raspberry Pi จริง
2. รองรับ HDMI-CEC แบบ native บนอุปกรณ์แสดงผลให้สมบูรณ์ยิ่งขึ้น
3. เสริมความปลอดภัยของการยืนยันตัวตนด้วย httpOnly cookie
4. รองรับหลายภาษา (i18n) ในส่วนจัดการ
5. ขยายระบบ CI/CD ให้ครอบคลุมการ deploy อัตโนมัติ
6. เพิ่มตารางข้อมูลแบบ time-series สำหรับ telemetry เพื่อวิเคราะห์แนวโน้มของอุปกรณ์

## 5.4 สิ่งที่ได้เรียนรู้จากการฝึกงาน

การปฏิบัติงานครั้งนี้ทำให้ผู้จัดทำได้เรียนรู้การพัฒนาระบบจากความต้องการใช้งานจริงอย่างครบวงจร ตั้งแต่การรวบรวมความต้องการจากผู้ใช้งาน การออกแบบสถาปัตยกรรมและฐานข้อมูล ไปจนถึงการพัฒนา ทดสอบ และติดตั้งระบบ ได้ฝึกการทำงานร่วมกันเป็นทีมโดยแบ่งความรับผิดชอบระหว่างส่วนเซิร์ฟเวอร์ (Backend) และส่วนติดต่อผู้ใช้ (Frontend) ซึ่งต้องตกลงรูปแบบการเชื่อมต่อ (API) ร่วมกันให้ชัดเจนก่อนพัฒนาแต่ละฝั่ง

[[P1]]
ในด้านเทคนิค ผู้จัดทำได้ประสบการณ์การทำงานกับเทคโนโลยีหลายส่วนประกอบกัน ทั้งการพัฒนา API แบบ asynchronous การออกแบบระบบสิทธิ์และความปลอดภัย การเข้ารหัสคำสั่งระดับไบต์ตามโปรโตคอล HDMI-CEC และ RS-232 ตลอดจนการสร้างตัวจำลอง (emulator) ขึ้นมาตรวจสอบความถูกต้องของคำสั่งเมื่อยังไม่มีอุปกรณ์จริงให้ทดสอบ ซึ่งเป็นบทเรียนสำคัญว่างานที่ต้องเชื่อมต่อกับฮาร์ดแวร์ยังสามารถทดสอบได้อย่างเป็นระบบ นอกจากนี้ยังได้ใช้เครื่องมือมาตรฐานอุตสาหกรรม ได้แก่ Git ในการจัดการเวอร์ชันโค้ด Docker ในการติดตั้งระบบ และการเขียนชุดทดสอบอัตโนมัติ ซึ่งช่วยให้ตรวจพบข้อผิดพลาดได้ตั้งแต่ระหว่างการพัฒนา ประสบการณ์เหล่านี้สามารถนำไปประยุกต์ใช้ในการทำงานจริงต่อไปได้
[[/P1]]
